# Contributing

Pull requests and issues are welcome. This project continues from upstream, which
has paused incoming PRs — the whole point here is that patches have somewhere to go.

No CLA. No issue required before a PR. No fixed review cadence — small, focused
changes get looked at fastest.

## What this project is

A Matrix ↔ iMessage bridge: Go (bridgev2) on top of a Rust core
(`pkg/rustpushgo`) that wraps [rustpush](https://github.com/OpenBubbles/rustpush),
joined by a UniFFI FFI boundary.

It continues from [lrhodin/corten-matrix](https://github.com/lrhodin/corten-matrix)
and tracks upstream **1.1.0**; see *Differences from upstream* in the
[README](README.md#differences-from-upstream).

## You need a Mac

**macOS 13+ (Ventura or later).** There is no way around this: NAC validation
data is produced by Apple's `AAAbsintheContext` framework, which exists only on
macOS. The Makefile refuses to run anywhere else. Upstream's Linux support relies on
closed-source crates that are not in this tree, so a Linux build is not possible
here regardless of toolchain.

You also need:

- Xcode Command Line Tools (`xcode-select --install`)
- a checkout path **without spaces** — CGO and the linker cannot handle them
- roughly 10 GB free, mostly cargo build artifacts

Homebrew, Go, Rust, protobuf, libolm, libheif and tmux are installed for you on
the first build.

## Build and test

```bash
git clone https://github.com/Bijan-A/corten-matrix.git
cd corten-matrix
make
go test ./pkg/... ./imessage/...
```

**On Intel Macs**, the Makefile hardcodes the Apple Silicon Homebrew prefix
(`/opt/homebrew`). If `brew --prefix` prints `/usr/local`, plain `make` fails to
find `olm/olm.h`:

```bash
make CGO_CFLAGS="-I$(brew --prefix)/include" CGO_LDFLAGS="-L$(brew --prefix)/lib -L$PWD"
```

`pkg/connector`'s tests link `librustpushgo.a`, so they need those same CGO
flags — run `make` before `go test`.

A cold `cargo build --release` takes 20–40 minutes and is memory-hungry; on an
8 GB machine expect swapping. Rebuilds after a Go-only change take seconds.

Other targets: `make clean`, `make rust`, `make bindings`.

## House rules

**Never hand-edit `pkg/rustpushgo/rustpushgo.go` or `rustpushgo.h`.** They are
generated by `uniffi-bindgen-go`. See [AGENTS.md](AGENTS.md) for how to
regenerate, and note that changing an exported signature means everyone
rebuilding needs the generator.

**Keep `pkg/rustpushgo/src/lib.rs` changes small.** It is an 11k-line file, it is
the FFI surface, and a panic in the wrong place there takes down the APNs
receive loop for ten minutes. Upstream's panic hook silences panics from some
rustpush modules, so failures there can be invisible — if you call into rustpush
somewhere it can panic, guard it (`catch_unwind`) and log.

**Network config options change in three places at once** —
`pkg/imconfig/example-config.yaml`, the `IMConfig` struct in
`pkg/connector/config.go`, and `upgradeConfig`. Miss one and the option
silently vanishes on upgrade. [AGENTS.md](AGENTS.md) has the detail.

**Don't commit `third_party/rustpush-upstream/`.** It is cloned at the pinned
SHA at build time.

## Opening a PR

- Build it and run the tests first. CI only builds on tagged releases, so it
  will not catch a broken build for you.
- One logical change per PR.
- Explain the *why*, especially for Rust changes — what breaks without it.
- **Say what you tested.** "Ran it on my own bridge for two days" is genuinely
  valuable here. Much of this code only misbehaves against live Apple servers,
  and a lot of bugs are unreproducible on demand.
- If you cannot verify something, say so. An honest "I could not trigger this,
  but the guard is strictly safer than the current behaviour" is more useful
  than an overstated claim.

Good first contributions: **anything you have already patched locally to make
your own bridge work.** That is exactly how this project started.

## Reporting bugs

Include:

- what you expected and what happened
- `corten-matrix --version`, macOS version, and Mac architecture (`uname -m`)
- whether you built from source or downloaded a release
- relevant log lines from `~/.local/share/corten-matrix/logs/bridge.log`
  (structured JSON; `corten-matrix logs` renders it readably)

**Scrub before pasting.** Logs can contain phone numbers, Apple IDs, and room
IDs. The bridge scrubs message bodies by default, but handles and identifiers
are not scrubbed — see *Privacy* in the [README](README.md#privacy).

If the bridge stopped receiving, `grep` for `Process task gone` and
`receive_wedge_watchdog` and include what you find, plus timestamps.

## Releases

Tagging `v*` builds a universal macOS binary in CI and publishes it. Linux is
not built — see the README. Only maintainers can tag; you do not need to think
about this for a normal PR.
